## 四、阶段2：引擎标准化（2-3天）

**目标**：将现有5个Python引擎类改造为符合 `BaseEngine` 接口

### 4.1 六爻引擎（先行试点）

**修改文件**：
- `engines/liuyao/__init__.py`（新建）
- `engines/liuyao/paipan.py`（新建，从 `core/liuyao.py` 迁移）
- `engines/liuyao/analysis.py`（新建，提取分析逻辑）
- `engines/liuyao/explain.py`（新建，提取解释逻辑）

**修改原因**：六爻是5个引擎中最独立的，选为试点。将 `LiuYao` 类拆分为三阶段实现

**拆分策略**：
- `calculate()` ← `get_gua_by_coins()` + `_build_gua_from_yao()` + `_apply_najia()` + `_get_liuqin()` + `_get_liushou()`
- `analyze()` ← `_interpret()` 中的分析逻辑（提取为结构化分析）
- `explain()` ← `_interpret()` 中的文本生成（提取为自然语言生成）

**影响范围**：`api/bazi_api.py` 中的 `/liuyao` 端点（需更新import路径）
**回滚方案**：保留 `core/liuyao.py` 原文件，新建的 engines 模块独立

### 4.2 梅花易数引擎

**修改文件**：同六爻结构，`engines/meihua/` 下三个文件

- `analyze()` ← `_analyze_shengke()` + `_get_wanwu_leixiang()` 结构化
- `explain()` ← `_interpret()` 文本生成

### 4.3 奇门遁甲引擎

**修改文件**：`engines/qimen/` 下三个文件

**拆分策略**：

### 4.5 八字引擎（最后，最复杂）

## 十、风险与应对

### 10.1 风险矩阵

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 引擎拆分破坏现有计算逻辑 | 中 | 高 | 每个引擎拆分后立即运行 `test_exam.py` 验证准确率 |
| 前端断连（API路径变更） | 中 | 中 | 保留旧路由，新增 `/api/v1/` 前缀，旧路由转发到新路由 |
| 八字引擎迁移最复杂 | 高 | 中 | 最后做，积累经验，充分测试 |
| 规则配置语法错误 | 低 | 低 | YAML schema 校验，加载时抛清晰错误 |
| 知识库JSON格式错误 | 低 | 低 | JSON schema 校验 |

### 10.2 回滚策略

每个阶段完成后，Git commit一次。出现问题时：
1. `git diff` 查看变更
2. `git checkout <file>` 回滚单个文件
3. `git reset --hard <commit>` 回滚整个阶段

### 10.3 质量保障

- 每个阶段完成后运行 `python test_all.py` + `python test_exam.py`
- 引擎拆分后运行考试，确保准确率不低于拆分前
- API变更后手动测试前端关键路径
